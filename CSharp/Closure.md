# Closure
- 클로저는 함수 안의 함수라고도 불린다.
- 함수 안에 선언된 또 다른 함수나 [익명 메서드](delegate/Lambda/AnonymousMethod.md), [람다식](delegate/Lambda/Lambda.md)이 그것을 정의하고 있는 바깥 메서드의 로컬 변수를 포함했을 때, 그 메서드 or 익명 메서드 or 람다식을 클로저라 부른다.
- 기존 함수는 입력 파라미터에 의해 그 출력이 결정된다. 즉, 파라미터가 변하지 않는다면 결과 또한 변하지 않는다. 함수가 언제나 동일한 입력에 대해 동일한 출력을 하기 위해서는 객체처럼 상태를 갖거나 하는 일처럼 외부의 다른 상태에 의존해서는 안 된다.
- 따라서 일반적으로 함수형 프로그래밍의 함수는 입력 파라미터와 그 함수 내의 로컬변수만을 사용하며 외부의 다른 상태에 의존하지 않는다.
- 클로저는 바깥 함수의 로컬 변수를 사용하면서도 그 자유 변수(Free Variable)을 내부로 끌어들여 포함하고 있는 일급함수이다. 이는 클로저를 일종의 데이터 타입처럼 취급해 다른 함수의 파라미터로 전달해서 사용할 수 있기 때문이다.
>클로저 선언 예시
```csharp
public void Case3()
{
	int Sqaure(int x) //클로저
	{
		return x * x;
	}

	int a = 10;
	int b = Sqaure(a);

	Console.WriteLine($"Case3 - Sqaure : {b}");
}

class Program
{
    public static void Main(string[] args)
    {
        Case3();
    }
}
```
- 하지만 클로저에는 메모리 누수 위험성이 있다. 클로저는 자신이 선언된 외부 범위의 변수를 캡쳐하여 유지하므로, delegate나 event에 등록된 후 해제하지 않으면 가비지 컬렉터가 메모리를 수집하지 못해 메모리 누수가 발생한다.
- 때문에 이벤트 구독 후 더 이상 필요하지 않으면 -= 연산자를 통해 해제해주어야 한다.
