# 게임 프로그래밍

- AABB 연산
    - 축이 정렬된 연산
- OOB 연산
    - 축이 회전된 연산
- 분리축 이론
    - 2D 및 3D 공간에서 두 개의 볼록 다각형이나 다면체가 서로 충돌했는지 판정하는 알고리즘. 두 물체를 분리하는 평면(축)이 존재하면 두 물체는 겹치지 않는 분리축 존재가 있으며, 가능한 모든 축에 대해 물체를 투영했을 때, 모든 축에서 투영 구간이 겹쳐야만 최종 충돌한 것으로 판정함. 단 하나의 축이라도 겹치지 않는 구간이 나오면 충돌하지 않은 것. 오직 볼록(Convex) 다각형과 다면체에만 적용할 수 있다는 한계가 있음.
- FSM
    - 상태(state)를 기반으로 동작을 제어하는 방식을 구현하기 위한 디자인 패턴.
    FSM의 핵심은 단 하나의 상태만을 가진다는 점으로 상태를 기준으로 어떤 동작을 수행할지 결정하기 때문에 현재 상태만 알 수 있으면 어떤 동작을 수행하려 하는지 명확히 파악할 수 있고 구현이 쉽다는 장점이 있음.
- PCB
    - 기판 위 마이크로컨트롤러(MCU)나 IC 칩에 코드를 다운로드하여 하드웨어가 특정 기능을 수행하도록 제어하는 과정
- 짐벌락
    - 3개의 회전축(Yaw(Y) Pitch(X) Roll(Z))이 겹쳤을 때 가운데에 있는 축이 90도 회전을 했을 경우 첫 번째 축과 두 번째 축의 회전 결과와 두 번째 축과 세 번째 축의 회전 결과가 똑같아 어디가 첫 번째와 세 번째 중 어디가 회전했는지 알 수 없어서 발생한다.
- [소프트웨어](../Software/Software.md)
- 코요테 점프(코요테 타임)
    - 떨어져도 점프를 할 수 있는 유예 기간.
- SerializeField
    - 유니티 에디터 프로세스와 실제 게임 프로세스는 서로 다른 프로세스지만, 상호간의 데이터를 공유해 개발을 원활히 하기 위해 게임에서 실행되는 코드를 에디터에 보여주는 것
- 입출력 장치
    - 컴퓨터 구조에서 시스템과 외부 세계(사용자 등) 간의 통신을 담당하는 하드웨어. RAM과 SSD 사이의 순서로 처리된다.
- 스트림
    - 데이터가 지나가는 통로 SSD → RAM에서도 RAM → SSD에서도 통로로서 기능, RAM이 byte형이므로 byte형을 가진다.
- 직렬화
    - 객체 → byte형의 배열로 변환하는 것. 입출력 장치를 통해 스트림으로 이동하는 데이터를 전달하기 위해 사용한다. C#은 메모리 관리가 자동인 대신 메모리 접근이 불가능하다.
- 패키지
    - 연관된 코드, 프로그램, 또는 데이터들을 하나의 묶음으로 압축하거나 배포하기 위한 형태.
- IPC(인터 프로세스 커뮤니케이션)
    - 독립된 프로세스들이 운영 체제(OS)의 지원을 받아 커널을 통해 데이터를 주고받거나 동기화를 수행하는 매커니즘.
- SDLC
    - 고품질 소프트웨어를 비용 및 시간 효율적으로 계획, 설계, 개발, 테스트, 배포 및 유지 관리하기 위한 체계적인 프로세스 프레임워크
- [다형성](../CSharp/Polymorphism.md)
    - 객체 지향 프로그래밍의 핵심 개념으로, 하나의 객체가 여러 가지 타입이나 형태를 가질 수 있는 성질, 하위 개념으로 가상화와 추상화를 지님.
- PBR
    - 빛과 재질의 물리적 상호작용을 컴퓨터 그래픽스로 정확하게 시뮬레이션하는 기술
- BRDF
    - 입력으로 입사각, 출사각, 법선벡터, roughness가 들어왔을 때, 특정 입사각으로 들어오는 광선이 반사광에 얼마나 기여하는가에 대한 분포 함수
- CBD(Component Based Development)
    - 재사용 가능한 컴포넌트의 개발 또는 상용 컴포넌트를 조합하여 하나의 새로운 응용 프로그램을 만드는 소프트웨어 개발 방법
- 결합도
    - 모듈(클래스 파일) 간의 상호 의존 정도 및 연관된 관계의 끈끈함을 의미함 결합도가 높은 클래스는 다른 클래스와의 연관 관계가 깊기 때문에 영향을 미칠 수 있음. 객체지향의 관점에서 결합도는 클래스 및 메서드가 협력에 필요한 적절한 수준의 관계만을 유지하고 있는지를 나타냄.
- 코드 스멜
    - 컴퓨터 프로그래밍 코드에서 더 심오한 문제를 일으킬 가능성이 있는 프로그램 소스 코드의 특징
- 리팩토링
    - 소프트웨어의 외부 동작을 변경하지 않고 내부 구조를 개선해 가독성을 높이고 유지보수를 용이하게 만드는 작업
- Validation
    - 개선사항을 실행한 후 사용자가 요구한 기능대로 시스템이 완성되었는지 확인하는 유효성 검사
- Verification
    - 개선사항 실행 전 개선을 위해 수립한 아이디어가 효과가 있는지 사전 테스트를 거치는 과정
- Skinning 기법
    - 3D 컴퓨터 그래픽스 및 골격 애니메이션에서 캐릭터의 3D 메시(외형)를 가상 뼈대(Skeleton/Bone)에 결합하여 자연스럽게 움직이도록 만드는 핵심 프로세스
- [다이어그램](Diagram.md)
    - 개발에 앞서 작성하는 일종의 프로그램 설계도
- C# 리플렉션
    - 타입을 변수처럼 사용하는 것
- .lib(Static Library)
    - 정적 라이브러리는 컴파일 타임에 호출자가 resolve 하는 루틴, 외부 함수, 변수의 집합으로 목적 파일과 단독 실행 파일 생성 중에 컴파일러와 링커에 의해 대상 애플리케이션에 복사된다.
- DLL(동적 링크 라이브러리)
    - 마이크로소프트 윈도우 운영 체제에서 여러 프로그램이 동시에 공유하여 사용할 수 있는 코드, 데이터, 리소스를 모아둔 파일.
- 해싱
    - 어떤 항목의 키만을 가지고 바로 항목이 들어 있는 배열의 인덱스를 결정하는 기법
- 상대 경로
    - 현재 작업 중인 파일이나 디렉터리를 기준으로 목표 파일의 위치를 찾아가는 경로 표시 방법
- LaTex
- [CPU](../Software/CPU/CPU.md)
    - 컴퓨터의 두뇌와도 같은 부품으로, 메모리에 저장된 명령어를 읽어들이고 실행하는 부품.
- Decorder
    - n비트의 2진 코드를 입력받아 최대 2의 n제곱개의 서로 다른 정보(또는 출력)로 변환해 주는 조합논리회로. 부호화된 데이터를 사람이 읽거나 컴퓨터가 인식할 수 있는 형태로 해독(복호화)하는 역할.
- Shifter
- [System Bus](../Software/CPU/Bus.md)
    - CPU가 메모리 등의 주변 장치들과 데이터를 주고받는 전기적 통로.
- Root Motion
    - 게임오브젝트의 위치와 회전을 Animation이 제어할 수 있도록 허용하는 것. Root Motion이 적용된 걷는 애니메이션은 캐릭터가 걷는 것에 따라 위치 값도 변하게 됨.
- [내적 벡터](../Math/Dot.md)
- [명령어 사이클](../Software/CPU/InstructionCycle.md)
    - CPU가 하나의 명령어를 처리하는 정형화된 흐름
- [캐시 메모리](../Software/CPU/CacheMemory.md)
    - CPU와 주기억장치(RAM) 사이의 속도 차이를 줄여 시스템 성능을 극대화하는 고속 버퍼 메모리
- [가상 메모리](../Software/CPU/VirtualMemory.md)
    - 물리적 메모리(RAM) 용량이 부족할 때 보조기억장치(SSD, HDD)의 일부를 메모리처럼 끌어다 쓰는 운영체제의 메모리 관리 기법
- 메모리 인터리빙
    - 물리적 메모리를 여러 개의 독립적인 모듈(뱅크)로 나누고, 연속된 주소를 서로 다른 뱅크에 번갈아 할당하여 동시 접근을 가능하게 하는 기법
- [메모리 단편화](../Software/CPU/MemoryFragmentation.md)
    - RAM에서 메모리의 공간이 작은 조각으로 나뉘어져 사용가능한 메모리가 충분히 존재하지만 할당(사용)이 불가능한 상태
- 가비지 컬렉션
    - 프로그래밍 언어에서 메모리 관리를 자동화하는 기술. 프로그램이 동적으로 할당한 메모리 영역 중 더 이상 사용하지 않는 불필요한 메모리(Garbage)를 시스템이 주기적으로 찾아내어 자동으로 해제.
- 더블 버퍼링
    - 두 개의 버퍼링을 준비하여 미리 그려진 버퍼링의 장면을 내보내는 동안 뒤에 있는 버퍼링이 다음 장면을 그리고, 앞 버퍼링의 장면이 끝나면 뒤 버퍼링에 그려진 다음 장면을 내보내는 것을 반복하는 기술
- V-Sync
    - 그래픽카드의 프레임 생성 속도를 모니터의 주사율에 맞춰 강제로 동기화하는 기술. 화면이 찢어지는 테어링(Tearing) 현상을 방지하는 데 쓰이지만, 프레임이 제한되며 입력 지연(Input Lag)이 발생할 수 있음.
- 프레임의 기준
    - 원래는 버퍼링에 장면이 그려지는 동안이나, 유니티에서는 업데이트 한 번으로 취급함
