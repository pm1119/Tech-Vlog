# 게임 프로그래밍

- AABB 연산
    - 축이 정렬된 연산
- OOB 연산
    - 축이 회전된 연산
- 분리축 이론
    - 2D 및 3D 공간에서 두 개의 볼록 다각형이나 다면체가 서로 충돌했는지 판정하는 알고리즘. 두 물체를 분리하는 평면(축)이 존재하면 두 물체는 겹치지 않는 분리축 존재가 있으며, 가능한 모든 축에 대해 물체를 투영했을 때, 모든 축에서 투영 구간이 겹쳐야만 최종 충돌한 것으로 판정함. 단 하나의 축이라도 겹치지 않는 구간이 나오면 충돌하지 않은 것. 오직 볼록(Convex) 다각형과 다면체에만 적용할 수 있다는 한계가 있음.
- FSM
    - 상태(state)를 기반으로 동작을 제어하는 방식을 구현하기 위한 디자인 패턴.
    FSM의 핵심은 단 하나의 상태만을 가진다는 점으로 상태를 기준으로 어떤 동작을 수행할지 결정하기 때문에 현재 상태만 알 수 있으면 어떤 동작을 수행하려 하는지 명확히 파악할 수 있고 구현이 쉽다는 장점이 있음.
- PCB
    - 기판 위 마이크로컨트롤러(MCU)나 IC 칩에 코드를 다운로드하여 하드웨어가 특정 기능을 수행하도록 제어하는 과정
- 짐벌락
    - 3개의 회전축(Yaw(Y) Pitch(X) Roll(Z))이 겹쳤을 때 가운데에 있는 축이 90도 회전을 했을 경우 첫 번째 축과 두 번째 축의 회전 결과와 두 번째 축과 세 번째 축의 회전 결과가 똑같아 어디가 첫 번째와 세 번째 중 어디가 회전했는지 알 수 없어서 발생한다.
- 소프트웨어 정의
    - 하드웨어 중심이던 시스템이나 인프라의 제어 및 기능을 소프트웨어 기반으로 가상화하여 프로그래밍과 자동화를 통해 유연하게 관리하는 기술 개념.
- 소프트웨어 특성
    - 하드웨어에 종속되지 않고 소프트웨어 계층에서 기능을 제어하여 시스템 변경 및 확장이 용이하기에 유용성과 확장성이 좋으며, 중앙의 컨트롤러를 통해 전체 시스템을 통합적으로 모니터링하고 자동화 정책을 적용할 수 있고, 값비싼 전용 하드웨어(Dedicated Hardware) 대신 범용 하드웨어 사용이 가능해 구축 및 운영 비용을 줄일 수 있다.
- 코요테 점프(코요테 타임)
    - 떨어져도 점프를 할 수 있는 유예 기간.
- SerializeField
    - 유니티 에디터 프로세스와 실제 게임 프로세스는 서로 다른 프로세스지만, 상호간의 데이터를 공유해 개발을 원활히 하기 위해 게임에서 실행되는 코드를 에디터에 보여주는 것
- 입출력 장치
    - 컴퓨터 구조에서 시스템과 외부 세계(사용자 등) 간의 통신을 담당하는 하드웨어.
- 스트림
    - 데이터가 지나가는 통로 SSD → RAM에서도 RAM → SSD에서도 통로로서 기능, RAM이 byte형이므로 byte형을 가진다.
- 직렬화
    - 객체 → byte형의 배열로 변환하는 것. 입출력 장치를 통해 스트림으로 이동하는 데이터를 전달하기 위해 사용한다. C#은 메모리 관리가 자동인 대신 메모리 접근이 불가능하다.
- 패키지
    - 연관된 코드, 프로그램, 또는 데이터들을 하나의 묶음으로 압축하거나 배포하기 위한 형태.
- IPC(인터 프로세스 커뮤니케이션)
    - 독립된 프로세스들이 운영 체제(OS)의 지원을 받아 커널을 통해 데이터를 주고받거나 동기화를 수행하는 매커니즘.
- 인터럽트
    - 준비 → 실행 → 대기 단계에서 대기 단계를 뜻하는 것.
- 소프트웨어 위기
    - 하드웨어 기술의 급격한 발전과 문제의 복잡성 증가로 인해, 소프트웨어 개발 비용, 일정, 품질 목표를 달성하지 못하고 유지보수에 큰 어려움을 겪는 현상.
- SDLC
    - 고품질 소프트웨어를 비용 및 시간 효율적으로 계획, 설계, 개발, 테스트, 배포 및 유지 관리하기 위한 체계적인 프로세스 프레임워크
- 다형성
    - 객체 지향 프로그래밍의 핵심 개념으로, 하나의 객체가 여러 가지 타입이나 형태를 가질 수 있는 성질, 하위 개념으로 가상화와 추상화를 지님.
        - 가상화(virtual)
            - 부모 클래스에 있는 것을 자식 클래스에서 재정의(override)하는 것
        - 추상화(abstract)
            - 부모 클래스에 없는 것을 자식 클래스에서 재정의(override)하는 것
- PBR
    - 빛과 재질의 물리적 상호작용을 컴퓨터 그래픽스로 정확하게 시뮬레이션하는 기술
- BRDF
    - 입력으로 입사각, 출사각, 법선벡터, roughness가 들어왔을 때, 특정 입사각으로 들어오는 광선이 반사광에 얼마나 기여하는가에 대한 분포 함수
- CBD(Component Based Development)
    - 재사용 가능한 컴포넌트의 개발 또는 상용 컴포넌트를 조합하여 하나의 새로운 응용 프로그램을 만드는 소프트웨어 개발 방법
- 결합도
    - 모듈(클래스 파일) 간의 상호 의존 정도 및 연관된 관계의 끈끈함을 의미함 결합도가 높은 클래스는 다른 클래스와의 연관 관계가 깊기 때문에 영향을 미칠 수 있음. 객체지향의 관점에서 결합도는 클래스 및 메서드가 협력에 필요한 적절한 수준의 관계만을 유지하고 있는지를 나타냄.
- 코드 스멜
    - 컴퓨터 프로그래밍 코드에서 더 심오한 문제를 일으킬 가능성이 있는 프로그램 소스 코드의 특징
- 리팩토링
    - 소프트웨어의 외부 동작을 변경하지 않고 내부 구조를 개선해 가독성을 높이고 유지보수를 용이하게 만드는 작업
- Validation
    - 개선사항을 실행한 후 사용자가 요구한 기능대로 시스템이 완성되었는지 확인하는 유효성 검사
- Verification
    - 개선사항 실행 전 개선을 위해 수립한 아이디어가 효과가 있는지 사전 테스트를 거치는 과정
- 추상 클래스
    - 객체 지향 프로그래밍에서 미완성 설계도와 같은 역할을 하는 클래스 추상화와 관련 있음
- Skinning 기법
    - 3D 컴퓨터 그래픽스 및 골격 애니메이션에서 캐릭터의 3D 메시(외형)를 가상 뼈대(Skeleton/Bone)에 결합하여 자연스럽게 움직이도록 만드는 핵심 프로세스
- 인터페이스:
- 유즈케이스 다이어그램
    - 유즈케이스 다이어그램은 사용자, 그리고 사용자가 수반한 다른 유스 케이스 간의 관계를 보여주는 사용자-시스템 간 상호작용의 표현. 유즈케이스 다이어그램은 각기 다른 종류의 시스템 사용자와 각기 다른 유스 케이스를 식별할 수 있으며 다른 유형의 다이어그램이 수반되기도 함
- 클래스 다이어그램
    - 구조 다이어그램으로 클래스 내부 구성요소 및 클래스 간의 관계를 도식화하여 시스템의 특정 모듈이나 일부 및 전체를 구조화함. 개발하기 전, 클래스 다이어그램을 그리게 되면 시스템 내 클래스 간의 의존성 파악과 팀원들 간 의사소통이 편리함.
- 시퀀스 다이어그램
    - 시계열(시간 순서)로 정렬된 객체 상호작용을 보여주는 것. 시나리오 기능을 수행하는데 필수적인 객체들 간에 교환되는 일련의 메시지들과 시나리오에 수반되는 객체와 클래스를 표현함. 시퀀스 다이어그램은 일반적으로 개발 중인 시스템의 논리적 뷰의 유즈 케이스 실현화와 관련됨.
- C# 리플렉션
    - 타입을 변수처럼 사용하는 것
- .lib(Static Library)
    - 정적 라이브러리는 컴파일 타임에 호출자가 resolve 하는 루틴, 외부 함수, 변수의 집합으로 목적 파일과 단독 실행 파일 생성 중에 컴파일러와 링커에 의해 대상 애플리케이션에 복사된다.
- DLL(동적 링크 라이브러리)
    - 마이크로소프트 윈도우 운영 체제에서 여러 프로그램이 동시에 공유하여 사용할 수 있는 코드, 데이터, 리소스를 모아둔 파일.
- PC(Program Counter)
    - 메모리에서 가져올 명령어의 주소, 즉 메모리에서 읽어 들일 명령어의 주소를 저장하는 레지스터. 프로그램 카운터를 명령어 포인터(Instruction Pointer)라고 부르는 CPU도 존재함.
- IR(Instruction Register)
    - 해석할 명령어, 즉 방금 메모리에서 읽어 들인 명령어를 저장하는레지스터. 제어장치는 명령어 레지스터 속 명령어를 받아들이고 이를 해석한 뒤 제어 신호를 내보냄.
- AC(Accumulator)
    - 중앙처리장치(CPU)의 산술논리장치(ALU)에서 산술 및 논리 연산의 중간 결과물을 단기적으로 저장하는 특수 목적 레지스터
- 해싱
    - 어떤 항목의 키만을 가지고 바로 항목이 들어 있는 배열의 인덱스를 결정하는 기법
- MAR(Memory Address Register)
    - 메모리의 주소를 저징하는 레지스터. CPU가 읽어들이고자 하는 주소 값을 주소 버스로 보낼 때 메모리 주소 레지스터를 거치게 됨.
- 상대 경로
    - 현재 작업 중인 파일이나 디렉터리를 기준으로 목표 파일의 위치를 찾아가는 경로 표시 방법
- LaTex
- MBR(Memory Buffer Register)
    - 메모리와 주고받을 값(데이터와 명령어)을 저장하는 레지스터. 즉, 메모리에 쓰고 싶은 값이나 메모리로부터 전달받은 값은 메모리 버퍼 레지스터를 거침. CPU가 주소 버스로 내보낼 값이 메모리 주소 레지스터를 거친다면, 데이터 버스로 주고받을 값은 메모리 버퍼 레지스터를 거침.
- ALU(산술논리연산장치)
    - 컴퓨터 내부에서 수행되는 계산을 도맡아 수행하는 컴퓨터의 부품
- Decorder
    - n비트의 2진 코드를 입력받아 최대 2의 n제곱개의 서로 다른 정보(또는 출력)로 변환해 주는 조합논리회로. 부호화된 데이터를 사람이 읽거나 컴퓨터가 인식할 수 있는 형태로 해독(복호화)하는 역할.
- Shifter
- Address Bus(주소 버스)
    - CPU의 메모리 주소 레지스터에서 메모리 간 데이터의 메모리 주소를 전달하는 부품.
- Data Bus(데이터 버스)
    - CPU의 메모리 버퍼 레지스터에서 메모리 간 데이터의 값을 전달하는 통로로 쓰이는 부품.
- Control Bus(제어 버스)
    - CPU의 제어장치에서 제어 신호를 메모리에 전달하는 부품.
- Root Motion
    - 게임오브젝트의 위치와 회전을 Animation이 제어할 수 있도록 허용하는 것. Root Motion이 적용된 걷는 애니메이션은 캐릭터가 걷는 것에 따라 위치 값도 변하게 됨.
- 내적 벡터
    - A벡터 * B벡터 * cos세타
- 인출 사이클
    - 메모리에 저장된 명령어 하나를 실행해야 한다 했을 때, 메모리에 있는 명령어를 CPU로 가져오는 사이클
- 간접 사이클
    - 명령어를 인출해 CPU로 가져왔다 하더라도 바로 실행할 수 없는 경우, 명령어를 실행하기 위해 한번 더 메모리에 접근하는 사이클.
- 실행 사이클
    - CPU로 가져온 명령어를 실행하는 사이클. 제어장치가 명령어 레지스터에 담긴 명령어를 해석하고 제어 신호를 발생시킴.
- 인터럽트 사이클
    - 인터럽트 요청 신호를 받은 CPU가 작업을 백업하고 인터럽트 플래그를 통해 인터럽트를 받아들일 수 있는지 여부를 확인하고 인터럽트를 받아들일 수 있을 경우 인터럽트 벡터를 참조해 인터럽트 서비스 루틴을 실행, 끝날 경우 백업해 둔 작업을 복구하고 실행을 재개하는 사이클
- 캐시 메모리
    - CPU와 주기억장치(RAM) 사이의 속도 차이를 줄여 시스템 성능을 극대화하는 고속 버퍼 메모리
    - 캐시 메모리 지역성:
        - 프로그램 실행 시 메모리에 균등하게 접근하지 않고, 특정 순간에 특정 데이터나 인접한 데이터를 집중적으로 참조하는 특성
    - 캐시 메모리 일관성
        - 여러 로컬 캐시에 저장된 공유 리소스 데이터의 균일성을 의미함. 캐시 일관성 시스템에서 여러 클라이언트가 공유 메모리 리소스의 동일한 영역에 대한 캐시된 복사본을 가지고 있다면, 모든 복사본은 동일함.
    - 캐시 메모리 매핑
        - 크기가 작은 캐시 메모리에 메인 메모리(RAM)의 데이터를 어떻게 배치할지 결정하는 방식
- 가상 메모리
    - 물리적 메모리(RAM) 용량이 부족할 때 보조기억장치(SSD, HDD)의 일부를 메모리처럼 끌어다 쓰는 운영체제의 메모리 관리 기법
    - 가상 메모리 관리정책
        - 물리 메모리(RAM)의 한계를 극복하기 위해 운영체제가 보조기억장치와 데이터를 주고받는 방식을 제어하는 핵심 규칙
    - 가상 메모리 페이징
        - 물리 메모리를 일정한 크기인 프레임으로 나누고, 논리 메모리를 프레임과 동일한 크기의 페이지로 나눔. 이후 필요한 페이지를 프레임에 적재하고 실행함. 각 페이지는 연속적이지 않은 공간에 존재할 수 있으며 각 프로세스는 각자의 페이지 테이블을 가짐
    - 가상 메모리 세그멘테이션
        - 프로그램을 고정된 크기가 아닌 함수, 데이터, 스택 등 논리적 의미 단위(Segment)로 나누어 메모리에 적재하는 기법
    - 가상 메모리 페이지드 세그멘테이션
        - 가상 메모리 관리에서 세그멘테이션의 논리적 보호 및 공유 기능과 페이징의 메모리 할당 효율성을 결합한 기법. 프로그램을 먼저 의미 단위의 세그먼트로 나누고, 각 세그먼트를 다시 고정된 크기의 페이지로 분할하여 주기억장치에 적재함.
    - Trashing
        - 가상 메모리 시스템에서 페이지 부재가 과도하게 발생하여 프로세스가 실제 작업보다 페이징 작업에 더 많은 시간을 소비하는 현상. 시스템이 페이지를 메모리에 적재하고 교체하는 작업에만 몰두하여 CPU 이용률이 급격히 저하되고 시스템 응답 시간이 현저히 증가함. 다중 프로그래밍 환경에서 메모리 부족 시 발생하는 심각한 성능 저하 문제.
- 메모리 인터리빙
    - 물리적 메모리를 여러 개의 독립적인 모듈(뱅크)로 나누고, 연속된 주소를 서로 다른 뱅크에 번갈아 할당하여 동시 접근을 가능하게 하는 기법
- 메모리 단편화
    - RAM에서 메모리의 공간이 작은 조각으로 나뉘어져 사용가능한 메모리가 충분히 존재하지만 할당(사용)이 불가능한 상태
    - 메모리 단편화 - 내부
        - 메모리를 할당할 때 프로세스가 필요한 양보다 더 큰 메모리가 할당되어 메모리 공간이 낭비되는 상황. 예를 들어 메모장을 틀었는데 OS가 10Kb 할당, 하지만 7kb만 사용하고 있을 때 필요 이상으로 프로세스가 메모리를 할당받았다면 내부 단편화 3kb만큼 생김.
    - 메모리 단편화 - 외부
    - 메모리 단편화 - 압축
        - 메모리 공간을 재배치하여 단편화로 인해 분산되어 있는 메모리 공간들을 하나로 합치는 기법
    - 메모리 단편화 - 메모리 풀
        - 필요한 크기 및 개수의 메모리 블록을 시스템으로부터 사전에 미리 할당(확보)해 두고, 프로그램이 필요할 때마다 이를 빌려주고 다 쓰면 반납받아 관리하는 기법
- 가비지 컬렉션
    - 프로그래밍 언어에서 메모리 관리를 자동화하는 기술. 프로그램이 동적으로 할당한 메모리 영역 중 더 이상 사용하지 않는 불필요한 메모리(Garbage)를 시스템이 주기적으로 찾아내어 자동으로 해제.
- 더블 버퍼링
    - 두 개의 버퍼링을 준비하여 미리 그려진 버퍼링의 장면을 내보내는 동안 뒤에 있는 버퍼링이 다음 장면을 그리고, 앞 버퍼링의 장면이 끝나면 뒤 버퍼링에 그려진 다음 장면을 내보내는 것을 반복하는 기술
- V-Sync
    - 그래픽카드의 프레임 생성 속도를 모니터의 주사율에 맞춰 강제로 동기화하는 기술. 화면이 찢어지는 테어링(Tearing) 현상을 방지하는 데 쓰이지만, 프레임이 제한되며 입력 지연(Input Lag)이 발생할 수 있음.
- 프레임의 기준
    - 원래는 버퍼링에 장면이 그려지는 동안이나, 유니티에서는 업데이트 한 번으로 취급함
- 컴파일러
    - 사람이 읽기 쉬운 고급 프로그래밍 언어 (C, C++, Java)로 작성된 소스 코드 전체를 컴퓨터가 직접 이해할 수 있는 저급 언어인 기계어나 어셈블리어 등으로 한 번에 번역하여 실행 파일을 만들어주는 소프트웨어 도구
- 인터프리터
    - 프로그래밍 언어의 소스 코드를 미리 기계어로 번역(컴파일)하지 않고, 한 줄씩 직접 읽어가며 즉시 실행하는 컴퓨터 프로그램 또는 환경
- 컴파일러 vs 인터프리터
- GPU
    - 그래픽 카드라고도 불리며, 대규모 데이터를 여러 코어로 나누어 동시에 처리하는 병렬 연산 특화 프로세서.
    - GPGPU
        - GPU의 범용 연산으로, CPU에서 처리하던 연산 작업을 GPU에서도 처리할 수 있게 해주는 것
    - CPU vs GPU
        - CPU는 소수의 코어로 복잡한 명령어를 순차적으로 처리하며, GPU는 수천 개의 코어로 단순 연산을 동시 처리함.
    - CUDA
        - 엔비디아에서 개발한 병렬 컴퓨팅 플랫폼 및 프로그래밍 모델. CPU가 순차적으로 처리하던 복잡한 연산을 GPU의 수많은 코어를 활용해 동시에 병렬 처리할 수 있게 해줌.
- RAM vs VRAM
- Compute Shader
    - 일반 렌더링 파이프라인과 별도로 그래픽 카드에서 실행되는 프로그램. 컴퓨트 셰이더는 대량 병렬 GPGPU 알고리즘 또는 게임 렌더링의 일부를 가속시키기 위해 사용할 수 있음.
- 프로세스
    - 운영체제로부터 자원을 할당받아 실행 중인 프로그램
- 프로세스 메모리 영역
    - 운영체제가 프로그램 실행을 위해 할당하는 코드(Code), 데이터(Data), 힙(Heap), 스택(Stack) 4가지 주요 구조로 나뉨.
    - 코드 영역
        - 실행할 프로그램의 명령어(바이너리 코드)가 저장되는 공간. CPU가 이 영역에서 명령어를 가져와 처리하며, 변경을 막기 위해 읽기 전용으로 설정되어 있음.
    - 데이터 영역
        - 프로그램의 실행과 함께 할당되며, 프로그램이 종료될 때까지 유지되는 전역 변수와 정적 변수가 저장되는 공간
    - 힙 영역
        - 프로그램 실행 중(런타임) 크기가 결정되는 동적 메모리 할당 영역으로, 프로그래머가 직접 메모리를 할당하고 해제하며, 객체나 동적 배열 등 크기가 유동적인 데이터, 즉 값을 저장하는 영역.
    - 스택 영역
        - 함수 호출 시 생성되는 지역 변수, 매개변수, 반환 주소 등 임시 데이터를 저장하는 메모리 공간으로, 흔히 데이터가 저장되는 주소, 즉 참조를 저장하는 곳이라고도 함.
