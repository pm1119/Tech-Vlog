# Object Pooling
- 유니티에서 사용하는 최적화 기법으로, 필요한 객체를 매번 새로 생성(Instantiate)하고 삭제(Destroy)하는 대신, 미리 일정한 개수를 만들어 풀(Pool, 웅덩이)에 보관해 두고 재사용하는 최적화 기법이다.
- 작동 방식
    - 초기화
        - 게임 시작 시 총알, 적, 이펙트 등 자주 쓰이는 객체를 미리 생성하여 비활성화 상태로 풀에 담아둔다.
    - 대여 (Get)
        - 객체가 필요할 때 풀에서 꺼내 활성화(SetActive(true))하고 위치나 방향을 설정해 사용한다.
    - 반환 (Return)
        - 사용이 끝난 객체를 완전히 삭제하는 대신 비활성화(SetActive(false))하여 다시 풀에 돌려놓는다.
- 주요 장점 및 단점
    - 장점
        - 성능 향상
            - 객체를 생성 및 삭제할 때 발생하는 CPU 연산 부하를 크게 줄여준다.
        - [가비지 컬렉션](../Software/GarbageCollector.md) 최소화
            - Destroy 함수 호출 시 발생하는 메모리 해제 및 가비지 컬렉션으로 인한 프레임 드랍(렉)을 방지한다.
        - 프레임 안정성
            - 대량의 오브젝트가 쏟아지는 환경(탄막 슈팅게임, 이펙트가 많은 전투 등)에서 일정한 프레임을 유지할 수 있다.
    - 단점
        - 초기 메모리 사용량
            - 게임 시작 시 미리 객체들을 생성해 두기 때문에 초기 로딩 시간과 메모리 점유율이 늘어난다.
        - 멀티플레이어 환경에 비적합
            - 네트워크 동기화 ID(예: 유니티의 ViewID 등)를 가진 객체를 무작정 풀링하면 ID가 꼬여 버그가 발생할 수 있으므로, 네트워크 객체는 로컬 시각 효과 위주로만 제한적으로 적용해야 한다.
